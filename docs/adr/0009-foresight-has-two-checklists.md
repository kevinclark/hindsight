# 9. Foresight has two checklists: the pit check before a match and the start of practice

Status: accepted, 2026-10-23; amended 2026-11-10 (the event checklist runs at the pit check, not in the queue)

## Decision

One engine, two checklists. **At the pit check before each match at an event** (amended; first written as "in the queue"): about seven items, the most critical first, done then
confirmed; each system gets Go, Go with deferrals (named) or No-go, as in a go/no-go poll. **At the start of a practice
session:** a longer list read and done in order (battery, CAN, cameras, zeros), ending in "ready to drive" or what is
left, with no Go verdict.

## Why

Checklist research for flight decks: critical items first, because interruptions skip the later ones; short lists;
read-do for a setup pass and do-confirm for a gate (Degani & Wiener, NASA CR-177549, 1990).

## Amendment, 2026-11-10: the pit check, not the queue

The first version put the event checklist in the queue. A real event's logs show no robot-on moment there: in one
team's 2026 event logs the robot booted 12–35 s before the field attached in 12 of 14 matches (the Driver Station and
the field attach in the same instant), and Foresight's field guard closes at the attach. The one moment before a match
when a tethered laptop can see the robot is the team's pit check, 18–29 minutes before most matches: one repeated run
(intake, spin up, score, some driving) on a practice battery, with a fresh battery put in at the queue. So the event
checklist runs there, and the pit check's enabled run is graded as it happens (On checks). Nothing else in the decision
changes: the same seven systems, do-confirm, Go / Go with deferrals / No-go. The match battery goes in after the last
moment Foresight sees the robot, so no checklist here can vouch for it; the battery line is context.
